# KIRIKO Design Signals 5分デモガイド

## 目的

「意匠情報から、市場・企業・商品化領域の先行シグナルを捉える」という目的を伝え、条件設定、分析結果、件数、根拠意匠の確認までを5分で体験してもらいます。結果は将来や企業戦略の断定ではなく、他の知財情報、商品情報、事業情報等と組み合わせる検討材料として説明します。

## デモ前チェック

- Draft PRの最新headに対応するPreviewを使い、Productionを開かない・変更しない。
- Previewに含まれるデータが完全な架空サンプルだけであることを確認する。
- 推奨プリセットで結果が0件にならず、件数と根拠意匠数が一致することを確認する。
- PC・モバイル・キーボード操作と、コンソールエラーがないことを確認する。
- 実データ、顧客固有情報、認証情報、ローカル環境の情報を画面・資料・スクリーンショットへ表示しない。
- 実データ配備状態が `BLOCKED_REAL_DATA_DEPLOY` のままであることを確認する。

## 0:00–0:40 目的

1. 製品名「KIRIKO Design Signals」と主メッセージを示す。
2. 意匠情報は、出願・権利化の確認に加え、市場・企業・商品化領域を検討する材料にもなると説明する。
3. 本アプリは傾向を俯瞰し、次の検討テーマを探すためのものであり、将来予測、企業戦略の特定、法的判断を行うものではないと伝える。
4. 公開Previewは完全な架空サンプルデータであることを短く明示する。

説明例:

> KIRIKO Design Signalsは、意匠情報を俯瞰し、市場動向、企業動向、商品化領域、デザイン変化の検討材料を得るためのアプリです。結果から根拠意匠へ戻れるので、傾向と元情報を行き来しながら次の確認テーマを探せます。

## 0:40–1:30 条件設定

推奨プリセットを1クリックで設定し、画面とDOMに並ぶ6段階を順に示します。

1. 分析対象を決める — 市場全体、特定業界、特定企業
2. 見たい領域を決める — 選択肢またはその他の入力
3. 対象となる意匠情報を決める — 物品、画像、空間、全対象。分析目的による自動設定と手動変更
4. 対象期間を決める — 現状把握は直近1年、傾向把握は直近2年
5. 分析目的を選ぶ — 市場動向、商品化領域、企業動向、デザイン変化、画像意匠の動向
6. 結果と根拠を確認する — 「分析を開始」から結果へ進む

出力部門は初回の必須入力ではなく、詳細設定を開かなくても分析を完了できることを伝えます。

## 1:30–3:00 分析結果

分析完了後、次の順に説明します。

1. 今回の分析対象意匠数
2. 注目トレンド
3. 商品化領域のヒント
4. 企業動向
5. 必要に応じたデザイン変化・画像意匠等の追加分析

各表現は参考傾向・検討材料として読み、断定しません。件数が表示され、根拠のない示唆が表示されないことも確認します。

## 3:00–4:10 根拠確認

1. 分析対象意匠数または注目トレンド等の件数をクリックする。
2. 対応する根拠意匠一覧へ移動し、表示件数がクリックした件数と一致することを確認する。
3. 1件を開き、企業名、物品名または画像の用途、意匠分類、登録番号、出願番号、公報番号、公報発行日、意匠種別、情報源、意匠の説明、取得済みの図面情報を示す。
4. 欠損値を推測・合成していないこと、図面画像本体と外部リンクが未接続であることを説明する。
5. 時間があれば企業・分類・物品名・意匠種別ランキングの件数からも同じ根拠一覧へ絞り込む。

## 4:10–5:00 展開可能性と現在地

1. 業界、企業、商品領域、期間、意匠種別に合わせて条件を変更できると説明する。
2. 現在版は架空サンプルの公開デモ、Git管理外ローカルJSONの限定検証、ルールベース分析、集計、根拠遷移、取得済み公報・図面情報の表示までと明示する。
3. LLM、外部情報、商用データベース、社内情報、図面画像の高度解析、自動監視、実データ配信は将来構想として区別する。
4. 実データは公開Preview・Productionへ配備しておらず、状態は `BLOCKED_REAL_DATA_DEPLOY` と伝える。
5. 相手が見たい分析、利用できるデータ、困っている工程を確認し、次回の専用デモまたはPoCへつなげる。

## 終了条件

- 5:00以内に目的、条件設定、結果、根拠、現在地まで説明できた。
- 件数から対応する根拠意匠一覧へ移動できた。
- 公開版が架空サンプルだけであることを明示した。
- 現在版と将来構想を混同しなかった。
- 実データ、顧客固有情報、認証情報を表示しなかった。
- Previewだけを使用し、Productionを変更しなかった。

## ローカルContract受入（非公開）

この手順は公開デモとは分離し、承認済みローカル環境だけで実施します。個別値、ファイル名、パス、hashはIssue・PR・コメント・ログへ記載しません。

1. Backendの正式run manifestが成功状態で、validated outputを一意に示していることを確認する。
2. FrontendがIssue #9のfinal headで、公開用fixture以外のJSONを含まないことを確認する。
3. ローカルサーバーを起動し、初期表示が架空サンプルモードであることを確認する。
4. 「詳細設定・データ情報」を開き、manifestが示すvalidated outputをFile API入力から直接選択する。Frontend配下へのcopyや移動は行わない。
5. Contract version、analysis cutoff、total/accepted/warning/quarantined/excluded、未解決項目の集計が表示されることを確認する。
6. 名称解決済みapplicantだけが企業候補に現れ、その候補で企業分析を実行できることを確認する。
7. 件数を選び、表示された根拠意匠数とstable evidence ID集合が一致することを確認する。
8. qualityとadapter dispositionを別項目として確認し、主分類/補助分類、publication、drawingを取得値のまま確認する。代表候補falseを公式な「いいえ」と表示しない。
9. PC、mobile、キーボード、focus遷移、console errorなしを確認する。
10. ページをreloadし、ローカルContract状態が消えて架空サンプルモードへ戻ることを確認する。

入力はブラウザのメモリ上だけで扱い、`localStorage`、IndexedDB、service worker、公開Preview、Productionへ保存・送信しません。
