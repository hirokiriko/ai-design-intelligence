# 現在版と将来構想

| 項目 | 現在版 | 将来構想 | 着手条件 |
| --- | --- | --- | --- |
| 公開データ | 架空のサンプルデータのみ | 承認済み実データの保護配信 | 安全な保存先、同一オリジンAPI、権限・監査設計 |
| 実データ検証 | Git管理外のローカルJSONをFile APIで読込 | 更新処理と保護APIを使った限定試行 | データ利用承認、運用責任者、削除・更新手順 |
| 分析方式 | 決定論的なルールベース分析 | 必要性が確認できた場合の高度分析 | 費用、機密性、品質評価、安全な構成の合意 |
| ランキング | 企業・分類・物品名・意匠種別から根拠一覧へ絞込 | 時系列比較や追加分類 | 対象期間と分類品質の合意 |
| 根拠確認 | レコードIDと取得済みメタデータを表示 | 公報・図面画像・外部リンク | 著作権、利用条件、リンク方針の確認 |
| 外部情報 | 未接続 | Web、プレス、新聞、株主総会、IR情報の照合候補 | 出典、利用規約、取得方法、更新責任の合意 |
| 配布 | 認証付きPreviewと公開サンプル | 限定トライアルまたは本番運用 | セキュリティレビュー、受入基準、運用費承認 |

## 現在の制約

- 実データをGit、公開ビルド、Previewへ追加しない。
- `/api/demo-designs` は未実装で、保護データ読込UIは既定で非表示。
- 実データ配備は `BLOCKED_REAL_DATA_DEPLOY`。
- Preview更新はProductionへの反映・昇格を意味しない。
- 分析結果は参考情報であり、法的助言ではない。

## 次フェーズの判定ゲート

1. 対象データと利用目的を承認する。
2. 保存場所、配信経路、認証、監査、削除手順を決める。
3. 小規模な限定試行の受入基準を定義する。
4. 技術・法務・運用レビューを完了する。
5. Previewで検証し、Production変更は別承認とする。
