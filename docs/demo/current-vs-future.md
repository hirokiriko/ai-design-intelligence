# KIRIKO Design Signals — 現在版と将来構想

将来構想を実装済みの機能として説明しません。現在版の分析結果も、将来や企業戦略を断定するものではなく、他の情報と組み合わせる検討材料です。

| 項目 | 現在版 | 将来構想 | 着手条件 |
| --- | --- | --- | --- |
| 公開データ | 完全な架空サンプルのみ | 承認済み実データを扱う安全な配信方式 | 利用承認、保存先、認証、監査、削除手順の合意 |
| 実データ検証 | Git管理外のローカルJSONをFile APIで手動選択し、ブラウザのメモリ上だけで利用 | 承認済みデータの継続運用 | 運用責任者、更新・保存・削除手順、受入基準の合意 |
| 分析方式 | 決定論的なルールベース分析 | LLM等による高度分析 | 必要性、費用、機密性、品質、安全性の評価 |
| 集計 | 企業、分類、物品名、意匠種別等の件数 | 時系列比較、追加分類、継続的な自動監視 | 対象期間、分類品質、更新責任の合意 |
| 結果 | 分析対象意匠数、注目トレンド、商品化領域のヒント、企業動向、追加分析 | 他の知財・商品・事業情報を含む複合分析 | データごとの出典、利用条件、評価方法の合意 |
| 根拠確認 | 結果・ランキングの件数から既存レコードIDの根拠一覧へ遷移 | 公報・図面画像・外部リンクの接続 | 著作権、利用条件、リンク方針の確認 |
| 外部情報 | 未接続 | プレスリリース、IR、Web商品情報、商用データベース、社内情報 | 出典、利用規約、取得方法、権限、更新責任の合意 |
| 図面 | 取得済みの公報・図面情報を表示。図面画像本体は未接続 | 図面画像の表示・高度解析 | 利用条件、権利処理、品質評価の合意 |

## 現在版のデータ境界

- 公開Preview、Production、公開ビルドには完全な架空サンプルだけを含める。
- 実データ、実在番号、画像、公報原本、顧客固有情報、認証情報をGitや公開ログへ含めない。
- ローカルJSONは利用者がFile APIで手動選択し、localStorage、IndexedDB、`public`、`dist`へ保存しない。
- 取得できていない値を推測・合成して公式情報のように表示しない。
- 図面画像本体と外部リンクが未接続であることを明示する。
- 実データ配備状態は `BLOCKED_REAL_DATA_DEPLOY`。
- Preview確認はProductionへの反映・昇格を意味しない。

## 次フェーズの判定ゲート

1. 対象データ、利用目的、利用権限を承認する。
2. 保存場所、配信経路、認証、監査、削除手順を決める。
3. 現在版と将来構想を分けた受入基準を定義する。
4. 小規模な限定試行で、件数、根拠、欠損値、表示境界を検証する。
5. 技術・法務・運用レビューを完了する。
6. Previewで検証し、Production変更は別承認とする。
